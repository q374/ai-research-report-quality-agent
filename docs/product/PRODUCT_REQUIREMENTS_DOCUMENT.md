# 产品需求文档：证据优先产品情报 Agent

版本：v1.0
更新时间：2026-09-20
阶段：本地 MVP，可用于求职作品集与受控演示
基线：DeerFlow v2.0.0

> 真实性边界：目标用户与痛点仍属于产品假设，尚未经过真实用户访谈；评测任务为合成任务；模型 API、运行数据、程序测试和本地界面验收均为真实执行。当前不是生产系统，不宣称准确率、真实用户增长或商业收入。

## 1. 一句话定义

面向 AI 产品经理和中小产品团队的证据优先研究 Agent：它不仅生成产品研究报告，还独立检查结论、来源、时效、范围和运行数据，并在对外发布前要求人工复核。

## 2. 背景与问题

通用研究 Agent 可以完成搜索和写作，但“运行成功”不等于“报告可以发布”。本项目的真实合成评测暴露了三类问题：

1. 使用官方来源，仍可能把历史事实写成当前事实；
2. 报告带链接，链接内容仍可能不支持对应结论；
3. 模型可能遗漏限制、自报错误字符数，或超出搜索与页面上限。

T001 同一任务的三次真实 API 结果分别为 67、79、36 分。提示词改善不稳定，因此产品从“继续改 Prompt”转向“生成、确定性校验、人工责任分层”。

## 3. 目标用户与核心场景

### 3.1 目标用户假设

- 需要做竞品、能力、价格或可用性研究的 AI 产品经理；
- 没有独立研究团队、但不能直接相信模型输出的中小产品团队；
- 需要为立项、路线图或内部汇报准备可追溯材料的产品负责人。

### 3.2 核心使用时刻

- 立项前快速核验市场与竞品事实；
- 版本规划前比较产品能力、限制和差异；
- 汇报前检查重要结论是否有直接来源；
- 报告发布前识别不可发布的风险项。

### 3.3 用户任务（JTBD）

当我要评估一个 AI 产品机会时，我希望系统自动收集可信资料、区分当前与历史、为关键结论绑定证据、暴露未知和冲突，并告诉我报告能否进入人工发布，从而减少机械核对，同时保留最终判断责任。

## 4. 产品目标与非目标

### 4.1 本期目标

1. 跑通“研究生成 → 证据提交 → 独立校验 → 人工复核”的完整闭环；
2. 把运行成功、质量可复核、人工允许发布拆成三个状态；
3. 让用户在聊天页直接看到质量状态、阻断原因和整改建议；
4. 保存 Token、工具调用、来源、报告哈希和人工决定，支持复盘；
5. 普通聊天不受影响，证据模式只对指定账号和研究配置启用。

### 4.2 本期非目标

- 不自动替用户作出投资、招聘、采购或上线决策；
- 不保证互联网信息绝对真实、完整或实时；
- 不实现无人值守自动发布；
- 不实现独立审核角色、多人会签和企业审批看板；
- 不建设生产级监控、计费、支付或多租户部署；
- 不把合成评测包装成真实用户研究。

## 5. 核心概念

| 概念 | 大白话解释 |
|---|---|
| 运行成功 | 程序完成了任务，不代表内容正确 |
| Claim | 模型提出的一条重要结论 |
| Evidence | 支持结论的来源、摘录和访问记录 |
| 确定性校验 | 用程序检查字符、次数、域名、引用和结构，不再调用第二个模型 |
| blocker | 必须解决，否则不能确认发布的问题 |
| report_hash | 报告版本指纹；内容变化后旧批准自动失效 |
| 人工复核 | 用户确认通过、退回修改或拒绝发布 |

## 6. 核心流程

1. **填写研究任务**：主题、对象、时间范围、必填维度、允许域名及资源上限；
2. **Agent 执行研究**：搜索、打开页面、提取资料并生成 Markdown 报告；
3. **提交结构化证据**：同一次运行提交 Claim、Evidence 和引用绑定；
4. **记录系统事实**：保存实际搜索、页面查看、工具调用、Token 和运行状态；
5. **确定性校验**：执行 EV-01 至 EV-12，生成 blocker、warning 和整改建议；
6. **展示质量卡**：原回答继续可见，质量卡说明是否建议发布；
7. **人工决定**：无 blocker 时可确认；也可填写理由后退回或拒绝；
8. **持久化与失效**：决定绑定报告哈希、复核人和时间；报告变化后重新校验。

## 7. 状态机与发布规则

| 状态 | 含义 | 用户可执行操作 |
|---|---|---|
| `blocked` | 存在阻断问题，不建议发布 | 查看原因、退回、拒绝；不能确认通过 |
| `review_required` | 自动检查未发现 blocker，仍需人工判断 | 确认通过、退回、拒绝 |
| `confirmed` | 当前报告版本已人工确认 | 查看决定与理由 |
| `rejected` | 当前报告版本被拒绝发布 | 查看决定与理由 |
| `validator_error` | 校验器异常或输入不足 | 失败关闭，不允许绕过 |

发布原则：任何 blocker、证据缺失或校验异常都不能自动进入 `confirmed`；`confirmed` 只说明“该版本已完成规定流程”，不等于事实绝对真实。

## 9. 质量规则

校验器覆盖以下类别：

- 当前事实与历史事实是否混淆；
- 结论是否绑定已访问、允许域名内的证据；
- 否定性结论是否把“未找到”误写成“没有”；
- 必填研究维度是否覆盖；
- 引用是否直接支持对应结论；
- 字符、搜索、页面和禁用工具是否超限；
- URL 是否重复、带锚点或别名；
- 未知项是否暗含无依据事实；
- 冲突、过期和审计字段是否完整；
- 证据摘录是否能在实际页面正文中找到。

确定性校验新增模型调用目标为 0；难以可靠自动判断的语义问题保留给人工。

## 10. 交互要求

### 10.1 聊天页

- 原报告持续可见，不因校验失败消失；
- 质量卡位于固定顶部栏下方，不得被遮挡；
- 质量卡显示状态、blocker/warning 数量、最多 3 条主要问题及建议；
- 普通聊天或没有校验记录时不显示质量卡。

### 10.2 人工复核

- `blocked` 不显示“确认通过”；
- `review_required` 可确认通过；
- 退回或拒绝必须输入理由；
- 网络重试不得产生重复决定；
- 报告版本冲突显示具体原因，而非通用错误。

## 11. 数据与审计

### 11.1 四层数据边界

1. **系统事实**：运行、工具、页面、Token、延迟；
2. **Agent 候选**：Claim、Evidence、引用关系；
3. **确定性判断**：规则结果和 finding；
4. **人工责任**：决定、理由、复核人、时间和报告哈希。

### 11.2 关键对象

- `ResearchBrief`：研究目标和约束；
- `Claim`：结论、类型、必填维度；
- `EvidenceItem`：URL、标题、摘录、访问事实；
- `ValidationRecord`：状态、指标、finding、报告哈希；
- `ReviewDecision`：人工决定及审计字段。

- 真实用户对来源、质量卡和审批流程的理解程度。

这些是待验证指标，不写成已达成 KPI。

## 13. 关键产品取舍

1. **不继续无限叠加 Prompt**：67 → 79 → 36 证明单次改善不稳定；
2. **不使用第二个模型当裁判**：避免新增幻觉、成本和延迟；
3. **先影子模式后硬门禁**：先验证真实数据链路，不破坏原回答体验；
4. **失败关闭**：缺数据和异常不能被解释成通过；
5. **普通聊天不启用证据模式**：把成本和复杂度留给高价值研究任务；
6. **审批绑定报告版本**：防止“改完内容仍沿用旧批准”。

## 14. 非功能要求

- **成本**：确定性校验不得新增模型调用；任何新付费样本需单独授权；
- **安全**：密钥只通过本地忽略文件或环境变量读取，不进入 Git、日志和文档；
- **权限**：读写均校验所有者，跨用户返回 404；
- **可靠性**：写入幂等，SQLite 迁移可重复启动，重启后状态可恢复；
- **可解释性**：每个阻断项必须有规则编号、原因和整改建议；
- **兼容性**：未启用证据模式的普通聊天保持原行为。

## 15. 当前验收结论

### 已完成

- DeerFlow + DeepSeek 基础回答闭环；
- 真实联网研究与多轮 Badcase 评测；
- 结构化证据、持久事件、独立校验和影子调度；
- 聊天页质量状态、原因和整改建议；
- 人工确认、退回、拒绝及版本绑定；
- 真实前端—Gateway—SQLite 联合验收；
- 实际登录账号页面已显示质量卡和复核控件。

### 仍未完成

- 实际账号提交人工决定后的持久化验收；
- 独立复核角色和多人会签；
- T002 至 T005 跨任务真实付费样本；
- 真实目标用户访谈和可用性测试；
- 生产部署、监控、告警和容量验证。

## 16. 三分钟演示路径

1. 打开真实 T001 v3 对话，展示可点击官方来源和 49.1K Token；
2. 展示实际登录页面中的质量卡，说明“回答成功不等于可发布”；
3. 打开真实结构化复测记录，展示 78,602 Token、1,079 字、6 次搜索、6 次页面和 `blocked`；
4. 展示 blocker 的规则编号、原因和整改建议；
5. 使用明确标注的零费用合成验收案例演示“确认通过 → 刷新 → Gateway 重启仍保留”；
6. 主动说明边界：当前是本地所有者自审 MVP，不是生产审批系统。

## 17. 后续优先级

### P1：验证产品价值

1. 访谈 3—5 名目标用户，验证研究场景、复核成本和发布风险；
2. 在新的单次费用授权下，从 T002—T005 选择 1—2 条跨场景样本；
3. 测量复核时长、误阻断、错误放行和人工分歧。

### P2：只有证据支持时再做

- 独立审核角色、多人会签和审批看板；
- 团队空间、生产部署和可观测性；
- 更复杂的自动语义判断。
