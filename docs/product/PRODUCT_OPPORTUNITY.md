# 产品机会与用户需求说明

更新时间：2026-09-19  
阶段：产品发现初稿，需求假设尚未经过真实用户访谈  
项目暂定名：Product Intelligence Agent（产品情报智能体）

## 1. 产品机会

AI 产品经理在立项、竞品分析和版本规划前，需要从官网、产品文档、新闻、公开报告等分散来源中提取事实，再整理成可比较、可追溯的结论。传统通用聊天产品可以快速总结，但容易出现来源缺失、事实与观点混淆、结论无法复核等问题。

本项目计划基于 DeerFlow 的任务拆解、搜索、工具和报告能力，构建一个“证据优先”的产品情报智能体：不仅给出结论，还要说明信息来自哪里、哪些是事实、哪些是推断、哪些仍需人工判断。

## 2. 目标用户假设

### 核心用户

- AI 产品经理
- 中小型 AI 产品团队的产品负责人
- 需要完成竞品和行业研究的产品运营或战略人员

### 核心使用时刻

- 新产品立项前，需要快速了解市场与竞品
- 制定版本路线图前，需要比较竞品能力和差异
- 面试或内部汇报前，需要整理一份有证据的研究材料

> 真实性边界：以上属于产品假设，目前没有真实用户访谈、问卷或生产行为数据支持。

## 3. 用户任务

当我要评估一个 AI 产品机会时，我希望输入研究主题、竞品范围和时间范围，系统能够自动收集可信资料、建立比较框架、标注证据和不确定性，并生成可供我复核的结构化报告，从而减少机械整理时间，把精力放在产品判断上。

## 4. 待验证痛点

1. 公开资料分散，手工搜索和整理流程重复。
2. 不同竞品信息口径不一致，难以直接比较。
3. 通用模型可能给出流畅但无证据的结论。
4. 资料可能过期，用户难以判断时效性。
5. 长报告生成成本和等待时间不可见，难以规模化控制。

这些痛点需要通过访谈、任务观察和样本评测验证，不能直接当作真实用户结论。

## 5. MVP 方案

### 输入

- 研究主题
- 竞品名称或筛选条件
- 时间范围
- 重点关注维度

### Agent 工作流

1. 将研究目标拆成子问题。
2. 搜索并收集公开来源。
3. 对来源进行去重、时效和可信度检查。
4. 提取可比较的产品事实。
5. 形成竞品矩阵、趋势判断和机会假设。
6. 为关键结论绑定来源，并标注不确定性。
7. 交给用户人工复核后导出报告。

### 输出

- 一页结论摘要
- 竞品比较矩阵
- 关键趋势和产品机会
- 证据链接及访问日期
- 不确定项与人工复核清单

## 6. MVP 边界

首版不做：

- 自动替用户作出投资、招聘或上线决策
- 保证互联网信息绝对真实或完整
- 未经人工复核直接对外发布报告
- 生产级实时监控、支付、复杂权限管理
- 将模拟题、公开资料测试包装成真实客户使用数据

## 7. 暂定验收指标

以下是试验目标，不是已达成结果：

| 维度 | 暂定指标 |
|---|---|
| 任务完成率 | 题集任务成功完成率不低于 90% |
| 关键结论证据覆盖 | 100% 有可访问来源 |
| 一般事实证据覆盖 | 不低于 90% |
| 高风险无依据结论 | 0 条 |
| 人工验收通过率 | 不低于 80% |
| 报告时效 | 公开来源需记录发布时间或访问日期 |
| 延迟 | 先测复杂任务基线，再确定正式目标 |
| 单次成本 | 先测复杂任务基线，暂不虚构阈值 |

自动评分只能筛查问题，不能替代重要结论的人工复核。

## 9. 第一阶段产品决策

1. 不把 DeerFlow 定位成普通聊天机器人，而是用于高价值、复杂、需要证据的研究任务。
2. 简单问答不应默认走完整 Agent 链路，否则上下文和辅助调用成本偏高。
3. 标题、推荐追问等功能需要单独衡量用户价值与额外成本。
4. 输出必须区分事实、推断和建议，并保留人工复核入口。
5. 只限制官方域名仍不足以保证正确性，还必须区分历史发布信息与当前产品状态。
6. 限制项提取、来源时效和“结论是否真的被引用支持”需要成为独立质量门禁。
7. 下一步先修正 T001 的证据判断，不立即扩张到更多付费评测。

## 10. 下一步验证

1. 研究质量门禁 v1.2 与 T001 v3 指令已完成免费人工走查，不调用模型。
2. 运行 T001 v3 前必须获得新的单次费用授权；未获授权时不执行 T001 v3 或 T002。
3. T001 v3 只有满足门禁、人工复核通过且得分不低于 80，才能决定是否扩展到 T002 至 T005。
4. 访谈 3 至 5 名目标用户，验证场景、痛点和付费意愿；未完成前不得声称需求已被真实用户验证。
